# ADR-0006. Стек прототипа и абстракция LLM-провайдера

**Дата:** 2026-09-02 · **Статус:** принято

## Контекст

Заказчик не ограничивает стек и прямо заявил, что не будет снижать оценку за выбор технологии; западные модели разрешены, поскольку обрабатываются открытые данные. При этом демо проходит вживую, и отказ внешнего API во время защиты обнуляет результат.

## Решение

Backend — Python + FastAPI, хранилище — SQLite, frontend — React + Vite. Python выбран из-за экосистемы сбора и разбора русскоязычного контента (feedparser, trafilatura, selectolax); React — потому что заказчик отдельно жаловался на табличное представление и ждёт нормальный интерфейс с карточками и фильтрами.

Доступ к моделям — через интерфейс `LLMProvider` с двумя реализациями: облачной как основной и запасной (локальная модель или отечественный провайдер) на случай отказа сети. Переключение — переменной окружения.

## Альтернативы

- **Streamlit.** Отвергнуто: рискует выглядеть как та же таблица, от которой уходит заказчик.
- **Next.js full-stack.** Отвергнуто: сбор и разбор российских источников на TypeScript заметно дороже.
- **Один жёстко зашитый провайдер.** Отвергнуто: единственная точка отказа ровно в момент защиты.

## Следствия

Два репозиторных слоя вместо одного и явный контракт API между ними — это как раз то, что позволяет двум инженерам работать параллельно. Стоимость абстракции провайдера — несколько часов и вторая настройка промптов; выигрыш — демо не зависит от доступности одного API.
