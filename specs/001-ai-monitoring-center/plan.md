## Summary

Система собирает материалы из RSS, сайтов регуляторов и публичных Telegram-каналов, приводит их к единому виду, формирует заземлённое саммари, разделяет на новости и НПА, оценивает влияние на конкретную компанию по методике заказчика и отдаёт ленту с фильтрами, поиском и полным ручным управлением содержимым. НПА живут отдельной сущностью с хронологией и историей оценок.

Технический стержень решения: **модель выставляет только баллы 0–3 по критериям с обоснованием, индекс и категорию вычисляет код по формуле заказчика**. Это даёт объяснимость, воспроизводимость, покритериальное измерение точности и настройку под другую компанию сменой конфигурации.

## Technical Context

**Language/Version**: Python 3.11+ (backend), TypeScript 5.x (frontend)

**Primary Dependencies**: FastAPI, SQLAlchemy, APScheduler, feedparser, trafilatura, selectolax, pydantic v2; React 18, Vite, TanStack Query, Tailwind

**Storage**: SQLite (файл в репозитории проекта, без внешнего сервиса)

**Testing**: pytest (контрактные и интеграционные тесты обработки), фикстуры на сохранённых HTML-снимках источников

**Target Platform**: локальный запуск на ноутбуке команды, демонстрация в браузере

**Project Type**: web application (backend + frontend)

**Performance Goals**: материал в ленте ≤15 мин после публикации (регуляторы ≤60 мин); обработка одной публикации 10–15 с; поиск и фильтры <1 с

**Constraints**: демо не должно зависеть от доступности одного внешнего API — обязателен резервный LLM-провайдер; работа без авторизации; объём данных прототипа — сотни материалов, не миллионы

**Scale/Scope**: 5–10 источников, 2 профиля компании, ~7 пользовательских историй, горизонт — демонстрация на защите

## Ключевые технические решения

Полное обоснование — в `research.md`. Кратко:

1. **Оценка**: LLM → баллы 0–3 + обоснование; индекс, категория и флаги — код. Конфиг `scoring.yaml` воспроизводит методику заказчика дословно.
2. **Заземление**: саммаризация возвращает утверждения вместе с цитатами из оригинала; проверка вхождения цитаты в исходный текст выполняется кодом, незаземлённое отбрасывается.
3. **Telegram**: публичная веб-версия `t.me/s/<channel>` без API-ключей (ADR-0004).
4. **НПА**: источник стадий и версий — `sozd.duma.gov.ru` и `regulation.gov.ru`; идентификатор акта служит ключом связывания материалов с досье.
5. **Дедупликация**: кластеризация по эмбеддингам заголовка и первых предложений с порогом, затем проверка моделью на различие позиций перед объединением.
6. **LLM-провайдер**: интерфейс с основной и резервной реализациями, переключение переменной окружения; все промпты версионируются, версия сохраняется в оценке.
7. **Планировщик**: APScheduler внутри процесса приложения. Очередь и воркеры не вводятся — на объёмах прототипа это лишняя сложность.
