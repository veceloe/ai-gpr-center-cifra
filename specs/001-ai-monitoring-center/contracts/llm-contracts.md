# Контракты вызовов модели

Границы того, что модели разрешено решать. Всё, чего здесь нет, решает код.

**Общее правило (конституция, принцип II):** модель возвращает только структурированные наблюдения — баллы, признаки, извлечённый текст. Она никогда не возвращает итоговую категорию, индекс, приоритет или решение о публикации в ленте.

Каждый промпт версионируется строкой вида `score_npa/v3`. Версия сохраняется в `Assessment.prompt_version` — без этого невозможно понять, к какой версии относится измеренное качество.

---

## Интерфейс провайдера

```python
class LLMProvider(Protocol):
    def complete_json(
        self,
        prompt_id: str,        # "summarize/v1"
        variables: dict,       # подстановки в шаблон
        schema: type[BaseModel],
        max_retries: int = 1,
    ) -> BaseModel: ...
```

Реализации: основная (облачная) и резервная. Выбор — переменной окружения `LLM_PROVIDER`. Обоснование — ADR-0006.

**Кеш.** Ключ — `sha256(prompt_id + model_id + normalized_input)`. Повторный прогон тех же материалов не обращается к сети: это делает демонстрацию мгновенной и защищает от исчерпания лимитов в момент защиты.

**Обработка невалидного ответа.** Валидация pydantic → при ошибке один повтор с добавленным указанием на нарушенное поле → при повторной неудаче материал сохраняется без оценки с признаком `assessment_failed` и попадает в ленту с явной пометкой. Материал не теряется никогда.

## LLM-01 · summarize — саммари с заземлением

**Вход:** текст материала, заголовок, тип источника.

**Выход:**

```json
{
  "claims": [
    {
      "statement": "ФЗ № 243-ФЗ вводит режим для больших фундаментальных моделей от 1 млрд параметров.",
      "quote": "режим для больших фундаментальных моделей (≥1 млрд параметров)"
    }
  ],
  "entities": {
    "who": ["Государственная Дума", "Минцифры"],
    "what": "Принят закон о поддержке развития технологий ИИ",
    "when": "26.07.2026, в силу с 01.09.2026",
    "consequences": "Маркировка ИИ-контента с 01.03.2027, переходный период до 09.2032"
  }
}
```

**Правила:**
- `quote` — дословный фрагмент исходного текста, не пересказ.
- 3–5 утверждений (FR-010).
- Если утверждение невозможно подтвердить цитатой — не включать его вовсе.

**Постобработка кодом (ступень 1):** проверка вхождения каждой `quote` в исходный текст после нормализации пробелов и типографики. Непрошедшие утверждения отбрасываются (FR-012). Выжившие уходят на ступень 2 — контракт LLM-06.

## LLM-02 · classify — тематика и идентификатор НПА

**Вход:** заголовок, саммари, URL источника, тип материала из `Item.item_type`.

**Выход:**

```json
{
  "act_identifier": "Законопроект № 1215252-8",
  "topic": "regulatory"
}
```

Тип материала не является выходом LLM: он копируется из `Source.item_type` при сборе (FR-013).
`topic` ∈ `regulatory` | `reputation` | `competitors` | `trends` (FR-014).
`act_identifier` заполняется только для материала с `Item.item_type = act`.
Backend канонизирует ключ досье из официального URL, когда это возможно, и не
использует общие ответы модели вроде «приказ» или «проект» как ключ `Act` (FR-036).

## LLM-03 · score_npa — баллы К1–К6

**Вход:** саммари и текст материала, профиль компании целиком, шкалы критериев из `docs/scoring-methodology.md`.

**Выход:**

```json
{
  "scores": { "К1": 3, "К2": 2, "К3": 3, "К4": 0, "К5": 0, "К6": 3 },
  "rationales": {
    "К1": "Обязательный переход операторов платного ТВ на CAS/DRM из реестра российского ПО — прямое влияние на ключевой продукт компании.",
    "К2": "Законопроект внесён в ГД, первое чтение — осенняя сессия 2026.",
    "К3": "Требует замены систем условного доступа у клиентов; прямое влияние на выручку.",
    "К4": "Действий на стороне компании не требуется — решение уже реестровое.",
    "К5": "Ответственность для компании не предусмотрена.",
    "К6": "Вступление с 01.01.2027, при исключении из реестра — 6 месяцев на замену."
  },
  "escalation_candidates": ["Акт относит доверенное ПО к стратегически значимым объектам"]
}
```

**Правила:**
- Каждый балл — целое 0–3, строго по шкале из методики.
- Обоснование ссылается на конкретный факт из материала и на конкретный пункт профиля компании.
- `escalation_candidates` — только из закрытого списка формулировок методики; свободные формулировки запрещены.

**Постобработка кодом:** вычисление ИВ по формуле, определение категории по шкале, применение флагов НПА: флаг делает итоговую категорию не ниже «Высокое», а «Критическое» остаётся «Критическое» (FR-016, FR-017).

**Релевантность выводится, а не запрашивается:** `is_relevant = (К1 > 0)`. Отдельный вызов на релевантность не делается — К1 «Применимость к деятельности» отвечает ровно на этот вопрос. Экономия одного вызова на материал и отсутствие противоречий между двумя разными ответами модели об одном и том же.

## LLM-04 · score_news — баллы Н1–Н4

**Вход:** саммари, дата публикации, текущая дата, профиль компании, шкалы Н1–Н4.

**Выход:**

```json
{
  "scores": { "Н1": 3, "Н2": 3, "Н3": 2, "Н4": 3 },
  "rationales": {
    "Н1": "Событие 12–20.08.2026, тема активно развивается, финальные предложения ожидаются в конце сентября.",
    "Н2": "Маркировка ИИ-контента напрямую затрагивает аудиовизуальные сервисы и продуктовую стратегию.",
    "Н3": "Затрагивает всю ИТ- и ТВ-отрасль РФ.",
    "Н4": "Новые шаги еженедельно, работа группы Совета по кодификации продолжается."
  }
}
```

`is_relevant = (Н2 > 0)`.

**Важно про Н1:** актуальность зависит от текущей даты, поэтому она передаётся явно. Иначе модель оценивает по своему представлению о «сейчас», и оценка «плывёт» при повторных прогонах.

## LLM-05 · dedup_pair — один факт или разные позиции

Вызывается только для пар, прошедших предварительный отбор по векторной близости (research R-05).

**Вход:** заголовки и саммари двух материалов.

**Выход:**

```json
{
  "relation": "same_fact",
  "reason": "Оба сообщают о внесении законопроекта № 1288702-8 в Госдуму 14.07.2026 без собственной оценки."
}
```

`relation` ∈ `same_fact` | `different_positions` | `unrelated`.

Объединение выполняется **только** при `same_fact` (FR-060). При `different_positions` материалы остаются раздельными (FR-061) — это прямое требование, вытекающее из предупреждения заказчика: объединение разных мнений уничтожает ценную разницу позиций.

## LLM-06 · verify_claims — вторая ступень заземления

Ловит misgrounded citation: цитата настоящая и в тексте есть, но приписанного утверждения не подтверждает. Первая ступень такое пропускает — обоснование в ADR-0007.

**Вход:** список пар «утверждение — цитата», прошедших проверку вхождения. Исходный текст материала НЕ передаётся: проверяется именно то, следует ли утверждение из приведённой цитаты.

**Выход:**

```json
{
  "verdicts": [
    { "index": 0, "entailed": true,  "reason": "Цитата прямо называет порог в 1 млрд параметров." },
    { "index": 1, "entailed": false, "reason": "Цитата говорит о вступлении в силу, но даты 01.03.2027 в ней нет." }
  ]
}
```

**Правила:**
- `entailed: true` только если утверждение следует из цитаты **целиком**. Частично подтверждённое — `false`.
- Отсутствие противоречия не есть подтверждение. Правдоподобное, но не сказанное в цитате — `false`.
- Все утверждения одного материала проверяются **одним вызовом**, а не по одному: это требование производительности из ADR-0007.

**Обязательное условие:** вызов выполняется **независимо от того, который сформировал саммари** — отдельный запрос без истории. Модель, оценивающая собственный вывод, измеряет согласие с самой собой.

**Постобработка кодом (ступень 2):** утверждения с `entailed: false` отбрасываются (FR-091). Вердикты обеих ступеней сохраняются по каждому утверждению (FR-092). Итоговое саммари собирается из выживших `statement`.

## Что модели не поручается никогда

| Не поручается | Почему | Кто делает |
|---|---|---|
| Итоговая категория влияния | невоспроизводимо, неизмеримо | формула + шкала в коде |
| Значение индекса | арифметика не задача LLM | код |
| Решение об исключении из ленты | производно от К1/Н2 | код |
| Применение флага эскалации | закрытый список условий | код по `escalation_candidates` |
| Объединение кластера | требует детерминированного правила | код по ответу LLM-05 |
| Перезапись правки пользователя | нарушает принцип IV | запрещено |
| Подтверждение собственного саммари | согласие модели с собой ничего не измеряет | отдельный вызов LLM-06 |

---

## Требования к измеримости

Каждый вызов логируется: `prompt_id`, версия, модель, длина входа, длительность, признак попадания в кеш, признак повтора после ошибки валидации.

Это даёт: замер SC-003 (10–15 секунд на публикацию), долю невалидных ответов как отдельную метрику качества промпта и возможность указать в отчёте, какая версия промпта дала заявленные проценты.
