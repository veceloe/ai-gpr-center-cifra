# ai-gpr-center-cifra

Интеллектуальный центр PR/GR-мониторинга для GS Labs. Кейс хакатона ITMO AI Product Hack, заказчик — ООО «Цифра» (GS Labs).

## Метод работы

Проект ведётся по **GitHub Spec Kit**. Спецификация — источник истины, код производен от неё.
Порядок: `/speckit-constitution` → `/speckit-specify` → `/speckit-clarify` → `/speckit-plan` → `/speckit-tasks` → `/speckit-analyze` → `/speckit-implement`.
Никогда не пиши код в обход `specs/001-ai-monitoring-center/tasks.md`. Изменение поведения = сначала правка `spec.md`.

## Обязательный контекст перед любой задачей

- `.specify/memory/constitution.md` — принципы, нарушать нельзя
- `specs/001-ai-monitoring-center/spec.md` — требования FR-### и критерии SC-###
- `docs/scoring-methodology.md` — методика К1–К6 / Н1–Н4 заказчика, менять только по ADR
- `docs/company-profile.md` — профиль компании, от него зависит вся оценка релевантности
- `docs/decisions/` — ADR: почему сделано так; не «оптимизируй» решение, не прочитав его ADR

## Жёсткие правила

- Индекс влияния считает **код по формуле**, не LLM. LLM выдаёт только баллы 0–3 с обоснованием.
- Любое утверждение в саммари должно быть подтверждено фрагментом оригинала. Нет подтверждения — не пиши.
- Правки пользователя никогда не затираются автоматической переобработкой.
- Исходный источник и его URL сохраняются всегда, ссылка на оригинал не теряется.
- Скоуп вне хакатона: авторизация, промышленная нагрузка, ИБ. Не реализовывать.

## Первоисточники

`context/` — материалы заказчика (кейс, Q&A, саммари созвона, Excel-реестр). Только чтение, не редактировать.
