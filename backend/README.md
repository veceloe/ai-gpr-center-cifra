# backend

Реализация по `specs/001-ai-monitoring-center/`. Код производен от спецификации: менять поведение — правкой `spec.md`, а не здесь.

## Запуск

Нужен Python ≥ 3.11.

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env          # заполнить LLM_API_KEY, при необходимости Telegram
export PYTHONPATH=.

python -m src.cli init-db
python -m src.cli seed-profiles     # профили компании из config/company_profile.yaml
python -m src.cli seed-sources      # 6 источников трёх типов из docs/sources.md
python -m src.api.main              # http://localhost:8000/api/health
```

Без `LLM_API_KEY` сервис поднимается, лента и управление источниками работают, обработка материалов — нет. Это осознанно: демо не должно падать из-за отсутствующего ключа.

## Команды

| Команда | Что делает |
|---|---|
| `init-db` | создать схему |
| `seed-profiles` | загрузить профили компании (FR-050) |
| `seed-sources` | загрузить базовый набор источников (FR-001) |
| `collect [--source-id N]` | разовый сбор |
| `process [--limit N]` | обработать необработанное: саммари, заземление, классификация, оценка |
| `parse-registry` | собрать эталон из Excel-реестра заказчика в `evals/registry_46.jsonl` (T017) |
| `verify-formula` | сверить формулу индекса с числами заказчика (T014) |
| `telegram-login` | однократная авторизация, печатает `TELEGRAM_STRING_SESSION` (ADR-0008) |

## Три решения, которые видно в коде

**Индекс считает код, не модель** (`src/scoring/formula.py`, ADR-0003). В контракте `ScoreResultRaw` нет полей `category` и `index_value` вовсе — модель физически не может их вернуть. Она выставляет баллы 0–3 с обоснованием, всё остальное вычисляется по `config/scoring.yaml`. Проверено: `verify-formula` сходится с Excel заказчика на 42 карточках.

**Заземление в две ступени** (`src/pipeline/grounding.py`, ADR-0007). Первая — вхождение дословной цитаты в оригинал, детерминированная проверка кодом. Вторая — отдельным вызовом модели: следует ли утверждение из этой цитаты. Вторая нужна потому, что первой недостаточно: настоящая цитата, не подтверждающая приписанное утверждение, проходит поиск по тексту. Отбракованные утверждения сохраняются с причиной — пользователь видит счётчик неподтверждённого.

**Правки пользователя не затираются** (`src/pipeline/runner.py`, принцип IV). Поле с записью в журнале правок пропускается при переобработке. Саммари не перезаписывается, а версионируется: машинная версия остаётся в истории.

## Известные ограничения

- Фронтенда нет: проверять через `/docs` или curl.
- Досье НПА (US3), дедупликация (US6) и дайджест (US7) не реализованы — маршрутов нет.
- `web`-адаптер собирает ссылки по типовым селекторам списков; для конкретного регулятора может потребоваться свой разбор.
- Качество на живой модели не измерено: нужен ключ и прогон `evaluate` (T083).
