# Конституция проекта «Интеллектуальный центр PR/GR-мониторинга»

## Основные принципы

### I. Ценность = эффект для конкретной компании (NON-NEGOTIABLE)

Материал оценивается не по «интересности», а по влиянию на конкретную компанию из профиля.
Каждая карточка обязана отвечать на вопрос «что это значит для нас», а не только «что произошло».
Материал без установленной связи с профилем компании — шум и не поднимается в ленте.
Основание: заказчик прямо противопоставил решение медиа-агрегаторам (Brand Analytics) — «оно есть, но не решает основную задачу».

### II. Детерминированная оценка, вероятностная только разметка (NON-NEGOTIABLE)

LLM выставляет только баллы 0–3 по критериям К1–К6 (НПА) и Н1–Н4 (новости) с текстовым обоснованием на каждый балл.
Итоговый индекс, категорию и флаги эскалации вычисляет код по формуле из `docs/scoring-methodology.md`.
Запрещено просить модель назвать «высокий/средний/низкий» напрямую.
Следствия: оценка воспроизводима, объяснима пользователю, измерима по-критериально и настраиваема весами без переобучения.

### III. Заземление на источник (NON-NEGOTIABLE)

Ни один факт в саммари не существует без подтверждающего фрагмента исходного текста.
Заземление проверяется в две ступени: цитата дословно содержится в оригинале И цитата подтверждает приписанное ей утверждение. Вторая ступень выполняется вызовом, независимым от того, который сформировал утверждение.
Каждая карточка хранит ссылку на оригинал, дату публикации и извлечённые цитаты-подтверждения.
Утверждение, не прошедшее любую из ступеней, не попадает в саммари.
Основание: подтверждённое требование заказчика «в саммари нет фактов, которых нет в оригинале»; вторая ступень добавлена по ADR-0007 после того, как исследование показало, что одной проверки вхождения недостаточно.
Формулировка «без галлюцинаций» запрещена: заявляется только измеренная величина с указанием метода.

### IV. Человек — редактор, а не потребитель

Система не заменяет специалиста. Любой продукт работы ИИ — саммари, категория, баллы, теги — редактируем.
Правка пользователя имеет приоритет над машинной и не затирается при переобработке.
Каждая правка сохраняется с указанием автора и времени и является рабочим материалом для оценки качества.
Основание: подтверждённая позиция заказчика «инструмент не должен рассматриваться как полная замена человека».

### V. Две сущности, два жизненных цикла

Новость — одноразовый материал: прочитал, решил, закрыл.
НПА — долгоживущее досье: стадии, версии, отзывы, слушания, изменение влияния вплоть до «принят и вступил в силу».
Единая карточка для обеих сущностей запрещена. Смешение — главная ошибка предыдущих попыток заказчика.

### VI. Демо важнее архитектуры

Критерий готовности — работающий сквозной пользовательский сценарий на живом демо, а не полнота слоёв.
Любая абстракция, не нужная для демонстрируемого сценария, откладывается.
Основание: «за выбор Python вместо Node.js, SQLite вместо PostgreSQL снижать оценку не планируют»; «важнее работающий MVP, чем промышленная архитектура».

## Границы скоупа

Вне скоупа и не реализуется: авторизация и разграничение прав, промышленная нагрузка и отказоустойчивость, информационная безопасность, отдельные модальности (аудио/видео).
Фокус — российские источники и российское законодательство. Зарубежные исследовательские инструменты признаны заказчиком нерабочими в этом контексте.
Прототип параметризуется под одну компанию. Попытка покрыть всю GS Group одним решением запрещена на этапе MVP.

## Рабочий процесс

Изменение поведения системы начинается с правки `spec.md`, а не кода.
Всякое требование имеет идентификатор FR-###, всякий критерий успеха — SC-###; задача в `tasks.md` ссылается на них.
Архитектурное или продуктовое решение, у которого была альтернатива, фиксируется как ADR в `docs/decisions/`.
Методика К1–К6 и Н1–Н4 принадлежит заказчику: изменение весов, шкал или формулы допускается только через ADR с явным обоснованием.
Ревью спецификации выполняет агент с чистым контекстом (`/speckit-analyze`), не тот, который её писал.

## Управление

Конституция имеет приоритет над остальными практиками и над предпочтениями отдельного участника.
Нарушение принципа NON-NEGOTIABLE — блокирующий дефект: задача не считается выполненной.
Нарушение прочих принципов допустимо только с записью в разделе Complexity Tracking файла `plan.md`, где указана отвергнутая простая альтернатива.
